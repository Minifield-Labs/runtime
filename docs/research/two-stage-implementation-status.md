## What is runnable now

The active workspace is an inference-only Rust implementation. It has no third-party tensor or inference runtime in the active CPU/WASM path. The thin `minifield-infer` executable accepts bounded plaintext from stdin, loads a caller-selected local bundle, runs the model, and writes plaintext to stdout. It does not select prompts, route tools, enforce product policy, call tools, use a network, or train a model. Those responsibilities remain with callers.

The custom execution path is:

- [`engines/engine-api`](../../crates/engine-api/src/lib.rs) defines checked shapes, layouts, dtypes, backend capabilities and identity, bounded resources, finite operation descriptors, opaque buffer leases, asynchronous completion polling, retirement, and token/candidate interfaces. Ownership checks include both an actual backend instance and a generation, so matching public numeric IDs alone are insufficient.
- [`crates/backend-cpu`](../../crates/backend-cpu/src/lib.rs) provides owned scalar F32 storage and the finite Rust kernels used by LFM2: checked copy and rectangular copy, embedding gather, add/multiply, linear projection, row/head RMS normalization, split-half RoPE, causal grouped-query attention, gated short convolution, and SwiGLU. It is a correctness baseline, not a throughput implementation.
- [`crates/executor-core`](../../crates/executor-core/src/lib.rs) parses a deliberately narrow LFM2 configuration, derives the exact typed tensor inventory, verifies and bounded-loads SafeTensors, expands F32 or BF16 storage into F32 compute buffers, and executes the dense LFM2 sequence. Its [config](../../crates/executor-core/src/lfm2/config.rs), [weights](../../crates/executor-core/src/lfm2/weights.rs), [loader](../../crates/executor-core/src/loader.rs), and [executor](../../crates/executor-core/src/lfm2/executor.rs) modules cover tied embedding/head semantics; convolution and attention cache state; masked known-token prefill and append; deep-copy fork; next logits; cancellation/failure isolation; and complete candidate scoring. Scores normalize every finite F32 logit over the full vocabulary using F64 intermediate math and reject a non-finite final F32 transport.
- [`crates/text-tokenizer`](../../crates/text-tokenizer/src/lib.rs) implements the pinned byte-level BPE profile in Rust. It validates caller-supplied JSON, handles exact added-token behavior, bounded BPE work, incremental UTF-8 decode, and explicit BOS only. Unmapped head IDs are rejected rather than discarded.
- [`crates/text-generation`](../../crates/text-generation/src/lib.rs) is a portable bounded greedy loop over a caller-provided tokenizer and token executor. It examines the full 65,536-score head, takes the lowest exact argmax tie, stops before emitting a caller-specified stop ID or when the output-token budget is reached, and rejects context-limit overflow.
- [`crates/infer-cli`](../../crates/infer-cli/src/lib.rs) and its [binary](../../crates/infer-cli/src/main.rs) are the native plaintext adapter. Bundle layout is `config.json`, `model.safetensors`, and `tokenizer/tokenizer.json`; BOS and token/context limits are explicit.
- [`engines/decoding-protocol`](../../crates/decoding-protocol/src/lib.rs) is a separate pure-Rust schema/argument-framing and teacher-trace component. It is available to a caller-side two-stage adapter, but the executor and plaintext binary do not depend on route selection, schemas, or tool execution.

The implemented model executor has been exercised on the externally stored, genuinely trained diagnostic LFM2 model. Its F32 weights have SHA-256 `ccb6771706166106908d040ba1131fc49037c613e0357e3d0f0cb1ef128115a3`, and its config has SHA-256 `1065cb6225b6ee3863e6a5b0bf7624db7f8b1898e7cd61a40fda13edadb9cf5f`. This artifact is development-only, not a released or useful-model qualification.

## What is not complete

The backend interface is extensible; it does **not** establish working arbitrary backends.

- CUDA and Metal have no active implementation or actual-device qualification. The workspace explicitly excludes `backends/cuda` and `backends/metal`. Earlier CUDA/Candle artifacts and isolated CUDA build records are historical prototype evidence, not part of the custom executor.
- Dense custom F32 has not completed a full pinned 350M forward/cache/scoring qualification. The loader's pinned-header check is not an inference run. BF16 compute, GPU numerical envelopes, large-context memory, cancellation during actual device work, and performance are unqualified.
- An external full-model QAT reference fixture contains INT8 group-64 codes/scales plus decoded values, logits and gradients. It is not a released packed model bundle; the runtime does not load or execute those quantized weights. There is no packed kernel, packed-memory claim, or QAT artifact acceptance. Its manifest is `fixtures/full-model-qat-001/manifest.json`, SHA-256 `07064cdcbc25c48ae4536bc1feac713db6c43f17d5aa931f55cfa7c7dd4c727a`.
- The browser result is a debug scalar CPU/WASM qualification. It does not establish release optimization, browser memory budgeting, persistent sessions, browser scheduling/cancellation, UI integration, or useful-model browser delivery.
- Generation is greedy only; sampling is not implemented and is not required for the current plaintext-executor scope. The plaintext CLI has no chat-template policy, tools, network service, product worker loop, schema-based route selection, or application-action execution.
- The optional two-stage caller remains an integration task. It must use executor prefill/append/fork/score from shared contexts and keep tool authorization and execution outside the binary. Corpus-derived capacity work must qualify at least the observed 8,658 logical-token maximum with a declared physical allocation bucket such as 12,288; neither is currently a runtime delivery claim.
- The tracked `src/**/*.mjs` helpers, tracked `engines/quant-reference`, and untracked `engines/lfm2-native/` prototype remain historical/legacy material. The latter is visible as an untracked working directory at this audit. The active workspace excludes the old engine, but repository-wide reference/business-branding cleanup is still work; this document does not claim it is finished.
